# AXOO Public Art 3D Studio — v2.2

Static browser-based public-art modeling editor. v1.5 review exchange is local and file-based; it is not real-time cloud collaboration.

## v2.2.1 — Click selection / no-outline exports / large OBJ smart framing

- **Left-click scene artwork or extra object:** reveals move/rotate/scale gizmo and a yellow 3D bounding-edge outline for clear visual selection. The yellow box is an editor helper placed outside source geometry, not a shader/material rewrite. This is an axis-aligned bounding *box* rather than an exact mesh contour.
- **Left-click site mesh, blank sky or ground, or press Escape:** dismisses both selection outline and XYZ axes. Left-drag continues to orbit without deselecting. Placement and measurement click modes retain their original priority. Approved MASTER can be visually selected for inspection while its transforms remain locked.
- **Fast framing always available above the viewport:** `선택 맞춤 (F)` or `현장 전체 (Shift+F)`. Selection focus uses a selected object when present, or the base artwork after deselection. Importing unusually large/distant-origin site models automatically focuses the imported site; the original world coordinates and mesh scale stay identical.
- **Huge site camera:** 800m OrbitControls ceiling no longer forces kilometer-scale OBJ models out of frame. Instead bounds-aware perspective distance, zoom range and camera near/far planes scale with the actual site dimensions; an explicit upper guard avoids unbounded numerical values. Large artwork primary import also receives bounds-fitting when appropriate. This is a camera-only operation and not automatic model rescaling or survey validation.
- **Export lock:** Yellow selection outlines appear only in the interactive 3D viewport. They are hidden for official PNG and MASTER eight-view captures. Exported GLB clones only source site/artwork/extras roots, so selection bounds are never part of the geometry payload. Browser regression confirms output with/without yellow outline is pixel-identical.

## v2.2 User Workflow Patch — curator-first modeling screen (October 2026)

Focused on fewer clicks and accurate art installations; no additional reports/PDFs were introduced.

- **Project name and quick archive:** The first scene panel provides a convenient one-click full project ZIP download and full ZIP import. Both operate through the established browser-local SHA-256 checked source archive. No online/cloud permanent storage is implied.
- **Smaller controls:** Non-essential site preflight, 2D plan overlay controls, and the temporary external GLB asset library controls are hidden (their internal compatibility and old ZIP metadata remain intact). Right-panel sections are individually collapsible, preserving the controls and scroll position. Narrow button groups wrap instead of overflowing to the right.
- **More than one art model:** The project retains a primary source art model plus up to **four independently imported GLB artworks**, for up to five in the scene. Newly added artworks use their exact original GLB mesh/materials and separate transforms; choose an artwork in the scene or object's list and delete it to reclaim the GLB slot. Each imported GLB must be self-contained and no more than 20MB; the combined project GLB library remains limited to 60MB. The full project ZIP includes their original source files. Deleting an extra artwork unloads its unused source and clears Undo history, so reimport the GLB to restore it.
- **Select-to-transform:** The position/rotation/scale 3D manipulator appears only after explicit artwork button or left-click object selection. Main scene startup no longer automatically overlays the object with axes.
- **Pedestals:** Rectangular and circular plinths, white (legacy concrete ID), metal and black finishes. Shape and finish are recorded with every plinth and survive project ZIP restore. Previously saved rectangular stone/concrete plinths remain supported.
- **Scaled figures/planting:** Human-scale schematic male 1.75m and female 1.60m mannequins, reproducible flowering shrub models. Detailed photogrammetric character accuracy is not claimed.
- **Uplight:** New ground-mounted `point-light` entries are upward-facing spotlights with a subtle transparent 3D cone to indicate direction, plus a real illumination source. Historical v1/v2 point-light objects retain the original omni-light presentation to avoid silently revising an approved older scene; deprecated standalone spotlight remains restorable for compatibility but is no longer offered as a new asset.
- **Clearer daytime shadows:** Reduced excessive hemispherical ambient lighting for new projects and revised clear/cloudy/golden light presets; actual visibility still depends on imported source normals, ground receiving shadows and sun direction.
- **3D measurements:** When measuring two site points, a red point–line–point with a world-distance meter label follows the screen camera. This is a view-only SVG overlay and does not enter the original geometry or rendered screenshots.

Limitations: additional artwork source import currently supports **GLB only**, while the primary artwork retains existing GLB/GLTF/OBJ/STL formats. Remote permanent model vault, precise BIM dimension certification and path-traced photographic realism are not implemented in this patch.

## v2.2 — Large site navigation / local focus / reversible scene clipping

This release prioritizes **working with large, faithful 3D architecture and landscape scenes**, not administrative reports or paperwork.

- **Site-only Ghost preview:** Choose **건물·조경 반투명 보기** from the inspector. Imported site mesh materials are temporarily cloned into 22%-opacity display materials while original sculpture and pedestal meshes remain fully opaque. All source site material pointers, maps, shader settings, mesh geometry and original per-mesh visibility are restored when the user resets the preview or exports images.
- **World-space local installation focus:** Show only scene meshes that intersect the sphere around the **actual artwork centre** at 15, 30, 60 or 120 metres, or return to full site. Culling uses source mesh world axis-aligned bounding boxes (coarse, conservative) and never rewrites, discards, or removes the imported geometry. Large enclosing site ground meshes may remain visible by design. The selected focus range is only a viewport aid, not an edited site layer.
- **Section/clip preview:** Choose X-left, X-right, Z-front, Z-rear or Y-above and optionally move the clipping plane ±100 viewer metres relative to artwork. Three.js local material clipping affects **site geometry only**; the artwork, pedestal, surroundings placed by the curator, and original building vertex data remain unaffected. This is an open geometric clip preview, **not a closed BIM section/cut volume**.
- **Adaptive navigation pixel density:** Optional **이동 중 픽셀 밀도 자동 낮춤** reduces preview device pixel ratio only during orbit/pan interaction and automatically restores full device pixel ratio when navigation ends. Saved/exported render resolutions stay independent.
- **Large scene stability:** Stable imported site mesh-path indexing is cached until a new source or site preset is loaded, reducing repeated scene traversals when changing layers. Preview processing is restricted to complete sites with **up to 10,000 site mesh objects**. For larger sites, the preview refuses partial clipping to avoid giving an inaccurate impression; users should simplify the imported model before using the feature.
- **Original-model integrity:** Ghost, section and local focus are explicitly **viewer-only**. When exporting normal PNG, MASTER eight-view ZIP, or GLB, original materials and complete original-source site visibility are restored first. Once the capture finishes, the preview resumes automatically. Preview settings are intentionally **not saved** with MASTER or project scene JSON. Existing manual layer hiding is a separate persisted scene change; a preview reset does not override it.

Verification: static/unit tests for clip-plane normals and local sphere culling, plus Chromium browser checks asserting a PNG exported with ghost/section enabled is **byte-identical** to the same original full-site PNG. This release **does not implement model-decimating LOD, geometry replacement or true out-of-core streaming**; these would require asset-specific preprocessing and accuracy verification.

## v2.1 — Precision dimensions, independent physical plinth, site XYZ anchors

This release continues the real-modeling-first workflow. No proposal, review PDF or administrative-document features are added.

- **Real W×D×H fit:** The artwork panel shows the current viewer world-aligned W / D / H size and lets the curator enter targets. Default `높이 기준 · 원래 비율 유지` adjusts all three scale axes uniformly to match target height; width/depth uniform modes also preserve the source proportions. Independent XYZ scaling is possible **only with explicit opt-in**, and is blocked for rotated artworks because their rotated world-axis bounds do not permit a simple exact XYZ scale solution. All size changes edit only the wrapper transform, NEVER original source geometry or mesh components. The artwork footprint center and bottom are preserved while scaling.
- **Physical 3D pedestal:** Enter plinth W/D/H (metres) and one of concrete / stone / metal PBR finishes, then use **작품 아래 기단 만들고 작품 높이 맞춤**. A separate, editable `plinth` 3D mesh is created at the current artwork footprint and the artwork is raised to the plinth top. Editing plinth dimensions and finish affects **only the plinth**; `선택한 기단 위로 작품 수평·높이 정렬` is an explicit, user-triggered alignment. Only one automatically linked plinth per primary artwork may be created; select it to change dimensions rather than stacking duplicates.
- **Attached-mount placement:** The plinth is on the editable artwork layer, and `followArtwork` metadata makes the linked mount follow the primary artwork when the user changes XYZ, drags the artwork or applies an XYZ installation anchor. Anchoring accounts for the full artwork-plus-plinth bounding box, so a ground reference point aligns the **base of the plinth**, not an elevated sculpture bottom. Site-click placement and ground adhesion likewise use the plinth bottom. Artwork-to-plinth **relative real size and material** still require site measurements and engineer review.
- **Site anchor precision:** Choose lower centre or one of the four world-axis artwork corners, then enter XYZ metres or click a real upward-facing site mesh to record the target. **작품 기준점 이동** applies a translation to the artwork and linked plinth without modifying source CAD/GLB geometry. These axes are *viewer world X/Y/Z*, not automatically inferred cardinal directions, geodetic survey coordinates or BIM origin labels. The optional `placementReference` is saved with a newly approved MASTER and available in the portable project JSON/ZIP. Invalid coordinates block MASTER approval.
- **Compatibility and QA:** New plinth objects retain dimensions, finishes and optional attachment through undo/redo and whole-project ZIP restore. Pre-v2.1 project files (without plinths or `placementReference`) remain valid. Any plinth changes after approval require the curator to unlock and explicitly reapprove a new MASTER; the v1.6 revision diff treats plinth changes as design-critical. No structural safety or certified installation clearance is inferred.

## v1.7 — Spatial Review Pins / 3D location-based review

Under **SPATIAL REVIEW**, enter the reviewer and detailed note, choose **3D 위치 클릭해 검토 핀 추가**, then click a visible artwork, site mesh or separate context object. Pins are placed at the actual WebGL ray-intersection world coordinate (viewer metres). Sample projects may use the visible schematic floor; imported real sites use their imported 3D geometry and never invent a clickable ground beyond it. Dragging only rotates/pans; Esc cancels pin placement.
- **Visual review markers:** Numbered badges float on top of the interactive viewport and track the camera as it orbits. They live in a separate HTML overlay, **not the Three.js scene graph**. They are not included in PNG/GLB renders, MASTER 8-view batch captures, source geometry or source materials. Click a marker or its right-hand list row to select the issue and inspect the note plus stored XYZ coordinates.
- **Status and versions:** Mark issues **미처리 / 처리 완료 / 다시 검토** under the current approved MASTER. Every pin is linked to the original approved revision, timestamp and canonical v1.5 SHA-256 MASTER fingerprint. Pins from a previous revision disappear from the current overlay automatically upon unlocking or approving the next revision, while the prior records remain in the project metadata. Maximum 80 pins per project. These notes are separate from mesh editing, and do not alter MASTER LOCK.
- **Storage and sharing:** Pins are saved under the optional `spatialReview` property of the v1.0 project config and thus included in both **whole-project ZIP** (with original source files and integrity manifest) and settings-only JSON. Clicking the 3D image does not certify a site measurement, structural safety, accessibility, artist permission or an authenticated reviewer. If an underlying 3D source changes, a different MASTER revision needs its own review pins.

## v1.6 — MASTER Revision Diff / track actual recorded design changes

- **Compare two approved MASTER snapshots:** The right sidebar now includes **REVISION DIFF**. Select an earlier and later approved revision; the read-only panel contrasts recorded installation position (viewer meters), rotation (degrees), X/Y/Z scale, artwork render materials, source filenames, plan alignment, lighting, camera, additional placed art/context objects, custom GLB manifests and layer annotations.
- **v1.6 MASTER fields:** Newly approved snapshots also record site unit, source up-axis and center-origin alignment. Those are lock-consistency fields for new snapshots and flagged as design-critical differences. Pre-v1.6 snapshots continue loading without these optional fields; such legacy site settings are marked **unverified**, never falsely labeled as confirmed changes.
- **Impact categories:** Critical artwork/site/source changes are differentiated from context/placement changes and presentation/render settings. View exactly what was recorded as different; tiny floating-point noise is suppressed. No model manipulation, rollback, unauthorized restyling or automatic adjustment is performed.
- **Export review report:** A one-click `axoo-master-revision-diff-v1` JSON contains revision pair, timestamp, changes, groups/counts, and SHA-256 fingerprints of both saved approved metadata snapshots. Because it uses the same canonical approved-snapshot fingerprint as the v1.5 team-review module, it can accompany the full project ZIP and human review JSON as a change log.
- **Boundaries:** This is a *saved metadata comparison*, **not a vertex-level comparison of model geometry**. Filename equality does not prove model-file checksum equality. Hidden native site or sculpture geometry, true measured site scale, materials embedded in GLB, structural safety, authorship and planning approvals must still be checked by the operator. Original source files never leave the browser.
- **Compatibility:** Existing v1.5 team-review and project ZIP/JSON persistence remain unchanged; older projects containing only one MASTER show a non-destructive hint until a second approved revision exists. Current editing/MASTER lock behavior and 8-view exports are preserved.

## v1.5 — Team Review / MASTER version tracking

- **Review request:** Approve and lock a MASTER, enter a requester and click **현재 MASTER 검토 요청 만들기**. Each request belongs to one approved MASTER snapshot, revision and approval timestamp. A SHA-256 digest of the canonical saved MASTER binds reviews to that exact artwork/site/material/placement state. A digest is NOT an identity signature.
- **Director response:** A reviewer different from the requester supplies a name and either enters explicit revision feedback (**수정 요청**) or checks the physical/visual human-verification attestation (**디렉터 수동 승인**). Statuses are pending, changes-requested and director-approved. Director approval is a manual review note, not an authenticated, legal, engineering, artist or public-agency approval.
- **Between devices:** The owner sends the **full project ZIP** with original sources/master history and the **review JSON**; the director opens the exact ZIP, reviews, records the decision, exports JSON and sends it back. The owner imports this result into the matching locked MASTER and saves a fresh full ZIP backup. No automatic upload or sync occurs.
- **Versioning:** Modification after feedback requires unlocking to start a new MASTER revision and another review request. The recent 40 MASTER revisions show review status; reviews survive whole-project ZIP round-trips. Older v1.4 ZIPs without this optional metadata remain compatible.
- **Safety:** Review never edits scene geometry, materials or camera. JSON imports are bounded and schema-validated, stale/nonmatching MASTER fingerprints are rejected, and notes display as plain text. Users must independently verify the sender and file origin. Simultaneous edits, online conflict merging, authentication, signatures and remote account permissions are intentionally out of scope.

## v1.3 — Advanced Modeling / measured scene edits

- **Multiple independent sculptures:** The v1.2 GLB library now accepts **별도 조형 작품** as an explicitly labeled fourth source category. Import a second sculpture GLB, place it on the site, transform it independently and protect it with the **artwork** layer (rather than landscaping). All original binary sources, instance IDs and materials are retained in SHA-256 portable ZIPs. This does not grant sculptural mesh editing; only root transforms are editable.

Existing context objects and GLB assets can also be duplicated. The main artwork always remains the original, and copies belong to the protected **artwork** layer, not decorative landscaping. Changing the base artwork while copies remain is blocked. Undo/Redo and full-project ZIP restore both preserve copies using the original artwork source binary; settings-only JSON requires the matching source to already be present. The current primary material preset synchronizes to duplicate materials.
- **Logical move-only groups:** Select at least two added objects with the checkboxes and choose **그룹 묶기**. Moving a grouped member by numeric XYZ or by releasing the translate gizmo moves the other editable group members by exactly the same translation. Rotation, scaling, source meshes and surface-snap behavior remain **individual**, not a rigid-transform Group hierarchy. The imported building/site cannot be grouped or edited. Group IDs are restored in Undo/Redo, scene JSON and ZIP.
- **Two-point surveyed-site-distance readout:** Click **현장 두 점 클릭해 거리 측정**, then two accessible site surface points. The panel displays 3D Euclidean distance, horizontal XZ distance and vertical height difference in **viewer metres** based on the current coordinate/unit conventions. No guessing of real-world survey measurements.
- **Object spacing:** Select two visible scene actors (artwork, duplicates or added context objects) to see world anchor-center separation, conservative axis-aligned 3D bounding-box gap, and whether their bounding-box volumes overlap. This is not a triangle-accurate minimum clearance solver.
- **AABB interference scan:** Reports overlapping **object/object** and **object/explicitly classified building** world AABBs for visible objects. Only site meshes manually categorized as `건물` in v0.6 layers are treated as a building. Floor planes, unclassified site geometry and invisible models do not count as building collisions. - **Audit report:** Save `precision-audit.json` including coordinates, measured distances, object pairing, group identifiers, building classification coverage and warnings. MASTER LOCK blocks duplication/group edits but permits read-only measurement/audit. Eight-view exports preserve the artwork-copy meshes, group state and scene positions, with standard MASTER revisions applied.

## v1.1 — Advanced Site Import / reliable project coordinates

- **GLTF ZIP import:** Real site models may be uploaded as a *.zip* containing **one glTF 2.0 `.gltf` plus its referenced external `.bin` and image files** (PNG, JPEG, WEBP). Direct GLB, standalone glTF, OBJ, FBX, STL, PLY, DAE, 3DS remain available. The ZIP is decoded locally with strict file/path checks (maximum 45 files, 100MB unpacked, 80MB input). External HTTP resources and upper-directory traversal are rejected. The **original ZIP bytes** are stored inside the portable studio project; reopening the whole project restores the exact source. This ZIP format is for *glTF 2.0 resources*, **not a generic archive of SKP/CAD/IFC/BIM files**.
- **Accurate site diagnostics:** Source mesh count, approximate triangle count, vertex count, distinct material count, source bounds/center and displayed dimensions in metres. Warns about large polygon counts, very distant model origin and implausible source size. Export the detailed **site preflight JSON**, with explicit caveat that it does not certify surveyed dimensions.
- **Local origin option:** For distant CAD/georeferenced site coordinates, the optional `뷰어 원점을 현장 모델 중심으로 맞추기` repositions **only the site parent group**. The source geometry, nested local transforms, materials and file bytes are untouched. The offset is recalculated on unit/up-axis edits to avoid cumulative drift, and saved/restored through the existing project ZIP/JSON as `site.alignment.centerOrigin`. Because artwork, plan overlay and other placed objects are *not* automatically translated, this is best selected **before** positioning/approving artwork.
- **Conversion instructions:** SKP, DWG, RVT and IFC are **not decoded natively**. Convert/export using trusted authoring tools to GLB or glTF ZIP; verify real units, mesh separation and whether textures or hidden building floors are preserved.
- **Risks:** Large geospatial models may suffer WebGL floating-point precision limitations even after recentering a parent group. A genuine georeferenced CAD tile-rebasing pipeline is separate future work. Always compare the result against original drawings and site measurements before approving MASTER.

## v0.8 approved MASTER 8-view render package

- **MASTER approval is mandatory** before batch rendering. The latest approved revision defines a canonical artwork placement, model identities, layer visibility, supplemental planting/lights and material selection. Changed locked elements block the export, rather than being silently used as a new MASTER.
- **8 standard viewpoints** are derived from that approved camera direction and its saved target: 01 Main Perspective (exact approved camera); 02 Eye Level; 03 Left ¾; 04 Right ¾; 05 Rear; 06 Aerial; 07 Long Shot; and 08 Close-up. They are mathematically derived camera views and do **not** change any artwork/site meshes. Architectural occlusion, pedestrian circulation and competition composition should still be reviewed manually. Side/rear directions are relative to the MASTER camera bearing, not a claimed true building north.
- **One-click batch PNG ZIP:** renders eight 16:9 images using selected 1× or 2× viewport-height quality (bounded by browser GPU maximum texture size and pixel budget); includes `render-manifest.json`, `REVIEW_NOTES.txt`, and optional 2-column `00-contact-sheet.png`. Temporary render camera, projection, sunlight and helper overlays are restored even on errors. The ZIP contains **renders and QA manifest only**; retain the separate full-project ZIP for source model files and editable state.
- **QA manifest & safety gates:** records approved revision, original files, measured *rendered mesh bounds* (not independently verified architectural survey), output sizes, per-view camera position/target/FOV, a scene identity/transform/material audit and limitations. Before rendering and after the capture pass, verify the latest approved artwork position, added-object transforms, site identity, layers and material preset. Detect in-memory mesh UUID, material references and placement changes across the batch. A failed check stops ZIP delivery.
- **Lighting:** uses saved approval lighting and environment mode where available. If the approval requires a missing custom HDRI, batch rendering refuses to substitute a generic studio environment silently. A previously saved v0.7 MASTER with no v0.8 record still works.
- **Accuracy limits:** This remains original Three.js WebGL PBR rendering, **not AI photorealization or a guaranteed CAD verification**. Human review remains necessary for true-scale dimensions, context, orientation, approved artwork components, and material realism. Do not represent the manifest as proof of artist consent or site approval.

## v0.7 architectural visualization / render controls

- **Photo-based environment reflection:** Load a local Radiance **.HDR** panorama (maximum 20MB) as an equirectangular environment for the WebGL PBR rendering. A ZIP package embeds the original HDR binary as `assets/environment` and restores it on reopen. Built-in "Neutral / Bright / Overcast" presets are **procedural studio reflection variations, not actual outdoor photographs or HDRIs**. Lighting intensity slider controls environment reflections. HDR does not upload to a web server.
- **Artwork material overrides are explicitly opt-in:** Default is **원본 유지**. The user can select and **Apply** painted metal, brushed or polished stainless steel, stone, clear or frosted glass. Override applies only to artwork meshes, not to the imported site or landscape. Original material references, textures and source asset files are preserved for an exact reset. Override and optional chosen color save in ZIP/JSON and Undo. **MASTER LOCK prevents changing artwork material** after approval; release requires an explicit new revision.
- **Lens and output framing:** Camera lens control is 16–120 mm equivalent for a 36mm gate. Output options include viewport, 16:9, 4:3, 3:2, 1:1, 4:5 and 9:16. Screenshot temporarily uses the specified target aspect and renders at 2–4× dimensions while respecting the maximum render texture size and safety budget; the **interactive camera position, aspect and field of view are restored** immediately. Helper grid, selection outlines, sun-position helper and editing gizmos are excluded from the PNG.
- **Persistence / backwards compatibility:** `render` property (settings-only JSON and complete ZIP) covers HDR filename, reflected intensity/mode, lens, framing and material override. Older v0.6 ZIPs with no `render` reopen with original artwork materials and default camera/environment. Render settings are applied without modifying geometry or scale. A settings-only JSON does not include the actual HDR file; upload the original .HDR again if needed.
- **Accuracy limits:** This remains Three.js WebGL **rasterized PBR imagery**, not path-traced/offline photorealism. Switching material can change the visual appearance of an artist-approved work, so apply only where the user expressly requests a revision. Complex transparency and custom textures may be approximated by simple preview presets. Physically accurate daylight, surveyed vegetation, photometric IES lights and AI reconstruction need separate validated workflows.

## v0.6 visual layers / scene object browser

- **Layer groups:** Show/hide imported site as a whole; independently show/hide source meshes explicitly classified as **건물/건축**, **기존 조경**, or **미분류 현장**; toggle artwork, newly added planting, and separately placed lights. Source meshes with no user classification remain **미분류**; filenames/names are not treated as reliable semantic survey data.
- **Site source hierarchy:** Expand the **현장 객체 분류** drawer, search up to the first 80 matching source meshes at once, inspect each mesh by highlighting its bounding box, manually categorize into building/landscape/unclassified and toggle its individual visibility. Imported site models **cannot be moved, deleted, sculpted or unlocked for transforms**. The layer engine only changes visible flags and stores stable index paths. If a source file merges all elements into one mesh, it cannot be individually separated in the browser without revising the 3D source.
- **Editable groups:** Artwork, added flora and lights may be selection-locked by group. Locks disable selection gizmos, numeric XYZ transformations, ground placement and deletion. The group visible flag filters scene rendering; hiding a layer doesn't remove the data or make it editable.
- **Individual extras:** Added trees/shrubs/point and spotlights each have eye and selection-lock toggles in their own collapsed layer list. Existing foliage shapes and object transforms remain unchanged. Actions support existing Undo/Redo.
- **Persistence & approval:** Layer grouping, visibility, selection locks and extra hidden/locked flags persist in settings JSON and complete-project ZIP. Approved MASTER snapshots include the same layer configuration and block changes until an explicitly confirmed revision. Older v0.5 files without layer settings reopen with all layers visible and unlocked where applicable.
- **Accuracy:** Model materials/geometry and original site architecture are untouched; hiding a mesh in the viewport may exclude it from a **visible-only GLB scene export**. The original uploaded site file is always kept intact inside the complete-project ZIP. Avoid confusing layer visibility with the existence of source geometry in the site.
- **Scale:** Mesh rows are limited to 80 matching results at a time to keep the inspector responsive; model data itself is never truncated.

## v0.5 precision placement & plan registration

- **Ground selected object:** Select the artwork, one of the three vegetation forms, or another editable scene object and click **선택 오브제 지면 밀착**. A downward world-space ray from the site finds a **generally upward-facing mesh surface** under the object's X/Z coordinates and adjusts the object's lowest bounding-box point to the mesh height plus an explicit offset. This preserves the artwork's geometry, material, rotation and relative scale. If the actual imported site has **no hit**, do not invent a zero-height ground plane.
- **Click-to-place:** Click **현장 클릭 재배치** then an upward-facing site mesh to move the chosen artwork or tree. Lights remain adjustable and are intentionally placed 3m above the selected point by default. **이동 완료 시 지면 자동 밀착** also grounds non-light objects after G moves and X/Z inspector edits. Undo/redo restores placements. SITE LOCK and MASTER LOCK remain in effect.
- **Plan overlay independent of ground mapping:** Loading a real site hides fallback ground material choices but **does not hide the separate optional 2D plan overlay**. User controls plan width (actual metres), center X/Z, rotation, vertical elevation, alpha, and visibility. Pick a site spot to set plan center. These are **manual registration tools**, not survey transformations, control points, auto-CAD conversion, or georeferencing.
- **Vegetation:** Newly added foliage uses deterministic trunk/branch and varied-tone leaf geometry, improving on the v0.4 broad polygon blobs while remaining lightweight schematic vegetation. **Old v0.4 project ZIPs without an appearance version continue to recreate their original vegetation shapes**, including approved MASTER layouts; newly placed assets are versioned separately. For competition-grade botanical realism, an external detailed/photogrammetry vegetation model or specialized rendering is still required.
- **Persistence:** Plan registration and grounding preferences save in existing settings JSON and full-project ZIP; prior v0.4 packages remain readable. Approval saves the plan alignment in its master snapshot and locks registration inputs.
- **Accuracy warning:** An upward-facing triangle can be a **roof, podium, raised slab or staircase landing**, not necessarily a surveyed pedestrian ground surface. Visually verify ground target before approving a MASTER VIEW; automatic ground detection cannot infer site semantics from an arbitrary mesh.

## v0.4 additions

- **Camera:** Mouse pan and rotate speeds increased; `nav-speed` slider adjusts OrbitControls pan/rotate/zoom. Remove the old full-width viewport footer; keep a small floating coordinates label.
- **Site calibration:** UI can scale an imported site's top-level transform from m/cm/mm/ft and rotate Z-up into world Y-up. Imported meshes and original file bytes stay unchanged. **Verify real-world dimensions**; some FBX/DAE loaders may have already converted units and should not be corrected twice.
- **Ground mapping:** Default ground textures and 2D plans remain as an optional fallback for dummy site presets, but are hidden after an actual site model is imported so they do not overwrite modeled paving.
- **Selectable environment assets:** Add a round canopy tree, pine/conifer tree, or shrub; point/spot lights can be placed directly on a clicked surface. Extra assets can be chosen by click or selection list, moved (G), rotated (R), scaled (S), deleted and restored with undo/redo. Supplemental foliage is **stylized concept geometry**, not existing-site survey data.
- **Lighting & sun indicator:** clear/cloudy/late-day/night presets, positionable point/spot lights (intensity/color), optional semi-transparent sun sphere. Sphere, editors and light-location icons are hidden during PNG capture and never added as export geometry.
- **Rendering:** 2x/3x/4x clean PNG capture of the actual 3D scene using ACES tonemapping, physically based materials, basic room reflections, soft shadows where supported. This improves presentation but **is not photographic AI reconstruction, Blender Cycles or offline path-tracing**. Higher settings depend on GPU and may consume significant memory.
- **Persistence:** Site unit/up selection, foliage, additional lights, camera speed and lighting preset persist through existing settings JSON and complete-project ZIP.

## User workflow

1. **현장**: Choose a schematic preset (plaza/courtyard/promenade/empty), or load an actual site **GLB / standalone GLTF / OBJ / FBX / STL / PLY / DAE / 3DS**. The three built-in presets are demonstrative massing only, **not real architecture**.
2. **배치도 참조**: Optional PNG/JPG/WebP map placed flat on ground. Enter the real measured horizontal map width in metres. **It is not photogrammetry**; site photos are not automatically converted to 3D.
3. **작품**: Load GLB/standalone GLTF/OBJ/STL, or use the dummy sample. The artwork's model shape/material parts remain intact; its pivot is centered horizontally and moved to ground. Imported artwork is **never automatically rescaled**: source W×H×D dimensions (interpreted as metres) are displayed. When units have been verified, the explicit **높이 맞춤** button proportionally scales the model to the entered real height.
4. **조작**: Click the artwork; G = move, R = rotate, S = scale, or click toolbar tools. Use the color-axis gizmo or precise X/Y/Z numbers. Proportional size lock is on by default. Holding right mouse to pan, wheel to zoom; left-drag on empty area to orbit. Grid and snap toggles are available; undo/redo saves transforms.
5. **빛 / 카메라**: Adjust sun azimuth, elevation, intensity, ambient lighting, exposure and shadows. Eight view presets are provided.
6. **승인**: MASTER VIEW approval saves an immutable snapshot of artwork transform, asset identity, camera, time, and lighting, then freezes artwork transforms **and site models/mapping**. Unlock requires explicit confirmation and starts a new revision. The Master History list and **승인 마스터의 카메라·조명으로 복귀** can restore any approved camera/lighting arrangement while leaving geometry in place.
7. **내보내기**: Preferred: **전체 프로젝트 ZIP 저장** creates a portable bundle with source artwork/site model bytes, optional plan image, transforms, lighting, camera, and master approval history. Importing this ZIP restores the project across sessions without choosing individual model files. PNG, GLB, and backwards-compatible settings-only JSON remain available.

## Constraints / known limitations

- The editor uses a **Y-up world and metre-based grid**, but **does not change or infer imported site-model units, scale, pivot or orientation**. GLB export from Blender with applied scale and Y-up conversion remains the best way to ensure coordinate and measurement consistency. Imported OBJ/STL/PLY/FBX/DAE/3DS files may use differing unit conventions and axes. Confirm their W×H×D readout against the plan before positioning artwork.
- **Site formats:** GLB, standalone GLTF, OBJ, FBX, STL, PLY, DAE (Collada), 3DS (legacy). The uploaded original binary/text file is saved inside the project ZIP. Geometry must include at least one mesh. Exporting the project as scene GLB remains available for cross-app use.
- **Not yet direct import:** SKP (SketchUp), IFC (BIM), RVT (Revit), DWG/DXF (CAD). Convert through SketchUp/Blender/FreeCAD or a compatible specialist exporter into GLB, preferably using real-world metres and Y-up. IFC-native semantics and precise surveyed coordinates require a separate dedicated import pipeline.
- A standalone `.gltf` works only if it embeds its binary/images. When its `.bin` and textures are external, **export a single `.glb` file instead**. OBJ material companion `.mtl` is not loaded; STL/PLY use a neutral PBR material (PLY embedded vertex colors are retained when available). FBX, DAE and 3DS may reference **external textures** that the single-file importer cannot resolve; such textures may be missing. Prefer a GLB with embedded textures for architectural render fidelity.
- Imported artwork is normalized to a center-ground pivot for editing. This intentionally discards the *object's world placement*, not its original mesh geometry, material colors, components or ratios.
- Site model remains **non-editable** to enforce SITE LOCK. Dummy site presets are explicitly not substitutes for verified real-site architecture or landscape.
- Settings-only JSON is retained for backwards compatibility, but does not include source assets. **Use the complete project ZIP for reliable recovery**; it includes original uploaded model bytes and plan image. ZIP compression runs inside the browser. Current size limits: ZIP 200 MB, each model 80 MB, plan image 20 MB.
- Map underlay remains an optional schematic reference plane for a preset site. A geospatially registered coordinate import and exact surveyed plan alignment are not implemented. Imported site files hide its fallback controls and use their own modeled ground.
- One artwork root is currently editable per scene; the additional flora/lights are separate transformable objects. Full CAD mesh sculpting and precise landscape planning are future extensions.
- Exact screen parity with `site-model-v1/artwork-v2/viewer/index.html` **has not been checked** because `file:///C:/...` paths are not reachable from the hosted repo.
- Three.js is loaded from pinned jsDelivr `three@0.186.1` and ZIP handling from pinned `jszip@3.10.1`; internet access is required on first page load. No user assets are sent to a server; the scene is client-side.
- A glTF/OBJ/STL file does not contain reliable metres metadata: units must be checked against real artwork W×D×H before manually applying a size change. Imported local transforms are left intact; only an external center-ground editing pivot is added.
- The ZIP restoration path is intended for project recovery, not collaborative cloud sync. Uploaded site files and artist assets remain on the user device; use the ZIP to archive or share with collaborators.
